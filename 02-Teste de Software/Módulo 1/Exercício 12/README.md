# Estratégia de Testes — Plataforma de Clínica de Psicologia

## 1. Objetivo

O objetivo desta estratégia é definir como serão realizados os testes da plataforma que simula uma clínica de psicologia.

A aplicação está atualmente na fase de **MVP (Minimum Viable Product)**. Os testes serão realizados durante o desenvolvimento para identificar bugs, problemas de usabilidade e falhas nas funcionalidades antes da evolução para novas versões.

---

## 2. Recursos e Cronograma

### Recursos

Serão utilizados os seguintes recursos:

- **9 pessoas** envolvidas nos testes;
- Cada participante utilizará seu **próprio computador**;
- A aplicação será disponibilizada em um ambiente de testes;
- Serão utilizados dados fictícios para realizar as simulações;
- Os bugs encontrados serão registrados para posterior correção.

### Cronograma

Os testes serão realizados em **ciclos semanais**, com duração de **1 semana por ciclo**.

O processo seguirá o seguinte fluxo:

**Desenvolvimento → Execução dos testes → Identificação de bugs → Registro e priorização → Correção → Reteste → Novo ciclo**

---

## 3. Pessoas Envolvidas

Serão **9 pessoas** envolvidas diretamente nos testes.

Cada participante deverá utilizar seu próprio computador para acessar a plataforma e realizar os testes definidos para cada ciclo.

A participação de diferentes pessoas permitirá avaliar a aplicação a partir de diferentes formas de utilização e aumentar a possibilidade de encontrar problemas.

---

## 4. Momento dos Testes

Os testes ocorrerão **durante todo o desenvolvimento da aplicação**.

Como o sistema está atualmente em fase de **MVP**, os testes serão iniciados nessa etapa e continuarão conforme novas funcionalidades forem desenvolvidas.

Não será aguardada a conclusão da aplicação para iniciar os testes.

---

## 5. Frequência dos Testes

Os testes serão **contínuos**, porém organizados em ciclos de uma semana.

Ao final de cada ciclo, os bugs encontrados serão analisados e os problemas prioritários serão encaminhados para correção.

Após as correções, será iniciado um novo ciclo, que terá como objetivo:

- Verificar se os bugs foram corrigidos;
- Realizar testes de regressão;
- Testar novas funcionalidades;
- Identificar novos problemas.

Esse processo continuará durante o desenvolvimento da aplicação.

---

## 6. Tipos de Testes

Durante os ciclos poderão ser realizados diferentes tipos de testes.

### Testes Funcionais

Verificar se as funcionalidades apresentam o comportamento esperado.

**Exemplo:** verificar se um usuário consegue realizar corretamente o agendamento de uma consulta.

### Testes de Usabilidade

Avaliar se a plataforma é fácil de utilizar, navegar e compreender.

### Testes de Validação

Verificar se campos e formulários aceitam apenas informações válidas e apresentam mensagens adequadas.

### Testes de Regressão

Após a correção de um bug, verificar se o problema foi resolvido e se a alteração não causou problemas em outras funcionalidades.

---

## 7. Registro de Bugs

Ao encontrar um problema, o participante deverá registrar informações que permitam sua reprodução e correção.

O registro deverá conter, sempre que possível:

- **Título:** resumo do problema;
- **Descrição:** explicação do que aconteceu;
- **Passos para reprodução:** como reproduzir o problema;
- **Resultado esperado:** o que deveria acontecer;
- **Resultado obtido:** o que realmente aconteceu;
- **Evidência:** captura de tela ou outra evidência;
- **Prioridade:** nível de importância do problema.

Os bugs serão analisados e priorizados pela equipe para definir quais deverão ser corrigidos primeiro.

---

## 8. Ciclo de Testes

Cada ciclo terá duração de uma semana e seguirá aproximadamente estas etapas:

### 1. Preparação

Definição das funcionalidades que serão testadas no ciclo.

### 2. Execução

Os 9 participantes realizam os testes utilizando seus próprios computadores.

### 3. Identificação

Os problemas encontrados são registrados como bugs.

### 4. Correção

A equipe de desenvolvimento analisa e corrige os bugs encontrados.

### 5. Reteste

Os participantes verificam se os problemas foram realmente solucionados.

### 6. Novo ciclo

Após as correções, inicia-se um novo ciclo de testes, incluindo novas funcionalidades e os testes das correções realizadas.

---

## 9. Critérios para Encerramento do Ciclo

Um ciclo poderá ser encerrado quando:

- As funcionalidades planejadas forem testadas;
- Os bugs encontrados forem registrados;
- Os problemas críticos forem identificados;
- As correções necessárias forem encaminhadas;
- Os testes previstos para a semana forem concluídos.

O encerramento de um ciclo **não representa o encerramento dos testes do projeto**. Um novo ciclo será iniciado após as correções e a evolução da aplicação.

---

---

## 11. Conclusão

A estratégia de testes será realizada de forma **contínua e iterativa**, acompanhando o desenvolvimento da plataforma desde a fase de MVP.

Os **9 participantes** realizarão os testes em seus próprios computadores durante ciclos de uma semana. Os bugs encontrados serão registrados, priorizados e corrigidos pela equipe de desenvolvimento.

Após as correções, novos testes serão realizados para validar as soluções e verificar se novos problemas foram introduzidos.

Dessa forma, a aplicação será constantemente avaliada e aprimorada ao longo de seu desenvolvimento, aumentando a qualidade e a estabilidade do sistema.
